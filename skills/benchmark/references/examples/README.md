# Saved Examples

Validated deliverables kept as quality references. One file per saved output.

## What goes here

A deliverable the consultant validated without reservation. Copy the validated version, do not rewrite it.

Naming: `[deliverable-type]-[market]-[year].md`, for example `exec-summary-assurance-emprunteur-2026.md`.

## When to read them

- Before Phase 0, to calibrate the level expected on a deliverable type
- After Phase 4 or 5, to compare a finished deliverable against a validated one

Never during an actor research run: rule S3 in SKILL.md. A reference deliverable read mid-research biases the findings.

## What does not go here

- Client data that should not be reused outside its mission
- Outputs the consultant corrected but never explicitly validated
- Full mission folders. Save the single deliverable file, not the run
